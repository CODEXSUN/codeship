# Registry environment key/value editor

Open Registry, select an application, and choose **Environment**. Variables use a compact bordered table: softly tinted key column, plain value column and pencil action on the right. Click a row's pencil to edit inline. Check/Enter applies the value to the draft; X/Escape cancels that row edit. The app-header Save persists the draft in encrypted SQLite. The row check is not an independent database save. A small status displays variable count, draft state and current record revision. Add variable creates an editable draft key/value row. No source `.env` file, running service or actual identity/password is changed by saving configuration.

Normal configuration values are loaded as text. Password/token/key/credential variables, credential-bearing URLs and unrecognized variable types are masked conservatively. A masked stored value is represented by bullets, not a literal string that could accidentally be saved. The eye action (accessible name Show/Hide plus the variable key) fetches that one value through the local record/key/revision-scoped POST endpoint; Hide clears an unchanged revealed value from editor state. Edited passwords remain available in the draft while masked so the user can save them. No secret values are written to browser local/session storage. Finishing a row edit returns it to the compact masked/plain display.

Ordinary application-list responses still contain no secret values. The environment row response contains null for masked values; explicit Show responses have Cache-Control: no-store and Pragma: no-cache. The existing loopback/approved-Docker-peer, local Host and exact-Origin rules protect both endpoints. The user's explicit request authorizes this targeted reveal; other credential fields and Infrastructure credentials remain write-only. There is no generic vault export, public-domain access or new production authentication flow.

Only edited rows are submitted. Untouched masked variables retain their exact stored values; an intentional edit to empty stores an empty value. Adding a variable uses uppercase letters, digits and underscores, starting with a letter. Duplicate draft keys and invalid/oversized input are rejected. The editor does not delete existing variables or silently rename them. A stale record revision rejects reveal or save and requires reloading; failed saves keep the draft on screen. Revealing a value does not mark it changed.

The source snapshot and managed environment are reconciled into the editor. SA/admin/user credential and metadata overrides are included. Environment edits to SUPER_ADMIN, TENANT_ADMIN or TENANT_USER account values synchronize the corresponding installation fields so an older override cannot defeat the edited `.env` value. This stores installation configuration only; it does not reset actual Platform identities.

Complete edited values remain encrypted. For local Docker targets, protected Node/Compose/transport/storage/execution controls are retained in the source snapshot but excluded from the managed runtime environment. Actual deployment identity still comes from the separately approved deployment profile. Changing a saved CODESHIP_HOST or HOST_PORT row does not expose the server or rewrite the trusted profile.

Values are single-line `.env` strings. Serialization chooses a quoting form supported by Node's parser and verifies lossless round-trip, preserving spaces, quote characters, dollar signs, hashes and backslashes. An unsupported quote combination or multiline/NUL input is rejected with a safe error rather than silently corrupting a secret. Raw `.env` replacement remains an internal/backward-compatible API option, but the Registry UI uses individual rows to avoid replacing unrelated values.

No schema migration is needed: values remain in the existing encrypted vault envelope. The normal image-only deployment skips database migration/backup and preserves data/key volumes. Focused tests exercise masking, explicit reveal, no-store headers, foreign-Origin denial, unchanged-value retention, empty/new values, encrypted persistence, stale conflicts, protected controls, account synchronization and quoting.

## Related table editors
Application, Users & secrets, and Infrastructure Service/Credentials/Maintenance use `@workspace/ui/blocks/inline-form-details`. Pencil opens a draft; check closes it, cancel restores the previous draft, and Save in the application header persists the whole form, including an open editor. Blank credential replacements preserve encrypted saved values. Stored credentials are masked; Show/Hide in these replacement fields does not retrieve saved credentials. Environment retains its revision-checked reveal endpoint.

The native frontend is http://127.0.0.1:4320 and proxies the API on 4325. The API also serves the latest built frontend on 4325. Native SQLite and Docker SQLite remain separate stores. Apply pending native migrations explicitly after an integrity-checked backup; never replace one store with the other as a UI refresh.
